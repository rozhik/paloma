# 06. Збереження файлів, метаданих та внутрішня база даних (Storage & Metadata)

Google Picasa використовує гібридну систему збереження даних: централізовану локальну базу даних для забезпечення високої швидкості роботи та приховані локальні файли конфігурації у кожній папці для забезпечення автономності й неруйнівного редагування.

---

## 📐 Архітектура збереження та обробки даних

```
+-----------------------------------------------------------------------------------------+
|                                  ФАЙЛОВА СИСТЕМА (ПК)                                   |
|                                                                                         |
|  📁 /Pictures/Vacation/                                                                 |
|  ├── 🖼️ photo1.jpg                 <-- Оригінал з вбудованими EXIF / IPTC / XMP         |
|  ├── ⚙️ .picasa.ini                 <-- Текстовий Sidecar з рецептами обробки та тегами |
|  └── 📁 .picasaoriginals/                                                               |
|      └── 🖼️ photo1.jpg             <-- Незмінений дублікат оригіналу (після Save)       |
|                                                                                         |
|  📁 %LOCALAPPDATA%/Google/Picasa3/db3/  <-- Центральна база даних (Binary .pmp / .pbf)    |
|  ├── 🗄️ albumdata.pmp / facedata.pmp    <-- Індекси облич, альбомів та фотографій        |
|  └── 🗄️ dbhash.xml / thumbs_index.db   <-- Кеш клейких мініатюр та хеші                 |
+-----------------------------------------------------------------------------------------+
```

## 1. Концепція неруйнівного редагування (Non-Destructive Editing)

Picasa **ніколи не модифікує оригінальний файл зображення** при застосуванні кадрування, ефектів або корекції кольору в редакторі.

1. **Рецепти змін (Edit Recipes):**
   * При зміні фотографії Picasa записує послідовність дій (інструкцій) у файл `.picasa.ini`.
   * Під час перегляду додаток на льоту накладає ці зміни на вихідне зображення в пам'яті.
2. **Операція "Save to Disk" та резервування (`.picasaoriginals`):**
   * Натискання кнопки "Save" створює приховану папку `.picasaoriginals` у тій самій директорії.
   * Незмінений оригінальний файл переміщується в `.picasaoriginals/photo1.jpg`.
   * Відредагований варіант "запікається" (bakes in) та записується на місце вихідного файлу `photo1.jpg`.
   * Натискання кнопки **"Revert to Original"** відновлює файл із `.picasaoriginals` та вилучає запис із `.picasa.ini`.

## 2. Формат службового файлу `.picasa.ini`

> 📘 Повна специфікація формату, складена за реальними файлами, — у [07-picasa-ini-format.md](07-picasa-ini-format.md). Приклад нижче спрощений.

Файл `.picasa.ini` — це прихований текстовий файл у кожній папці із зображеннями. Він побудований за стандартним синтаксисом INI-файлів.

### 📜 Приклад вмісту файлу `.picasa.ini`:

```ini
[Picasa]
name=Карпати 2024
date=45422.500000
P2category=Folders

[Contacts]
6a71f8e2190823ab=Олена Шевченко;olena@gmail.com;;

[IMG_0042.jpg]
caption=Схід сонця на вершині
star=yes
backuphash=52410
rotate=rotate(1)
crop=rect64(34901f42d2a4e8d8)
filters=crop64=1,34901f42d2a4e8d8;enhance=1;sepia=1;
faces=rect64(579922efa1cce2aa),6a71f8e2190823ab;
```

---

### 🔍 Детальна специфікація ключів `.picasa.ini`:

#### 1. `crop=rect64(...)` та `faces=rect64(...)` (64-бітне кодування прямокутників)
Picasa використовує 64-бітні шістнадцяткові рядки (16 hex-символів) для кодування нормованих координат прямокутників (кадрування або обличчя):

* **Приклад:** `rect64(579922efa1cce2aa)`
* **Алгоритм декодування:**
  1. Рядок розбивається на чотири 16-бітні підрядки (по 4 hex-символи):
     * `Left (X1)`   = `5799` (Hex) = `22425` (Dec)
     * `Top (Y1)`    = `22ef` (Hex) = `8943`  (Dec)
     * `Right (X2)`  = `a1cc` (Hex) = `41420` (Dec)
     * `Bottom (Y2)` = `e2aa` (Hex) = `58026` (Dec)
  2. Значення нормуються шляхом ділення на $65535$ ($2^{16}-1$):
     * $x_1 = 22425 / 65535 \approx 0.3421$ ($34.21\%$ від лівого краю)
     * $y_1 = 8943 / 65535 \approx 0.1364$ ($13.64\%$ від верхнього краю)
     * $x_2 = 41420 / 65535 \approx 0.6320$ ($63.20\%$ від лівого краю)
     * $y_2 = 58026 / 65535 \approx 0.8854$ ($88.54\%$ від верхнього краю)
  3. Для отримання абсолютних піксельних координат значення $x_1, x_2$ множаться на ширину зображення ($W$), а $y_1, y_2$ — на висоту ($H$).

#### 2. `filters=` (Послідовність застосованих ефектів)
Містить список фільтрів, розділених крапкою з комою.
* `enhance=1;` — Автокорекція кольору та контрасту.
* `sepia=1;` — Фільтр сепії.
* `bw=1;` — Чорно-білий фільтр.
* `radblur=1,x,y;` — Розмиття фокусу.

#### 3. `faces=rect64(...),contact_id`
Зв'язує прямокутник обличчя з ідентифікатором контакту із секції `[Contacts]`.

#### 4. `star=yes`
Позначення фотографії прапорцем "Обране" (Зірочка).

#### 5. `rotate=rotate(N)`
Поворот зображення ($1 = 90^\circ$, $2 = 180^\circ$, $3 = 270^\circ$).

## 3. Центральна база даних Picasa DB3

Для забезпечення швидкого пошуку та миттєвого відображення тисяч фотографій Picasa зберігає індекс у центральній двійковій базі даних DB3.

### 📂 Шляхи розміщення бази даних:
* **Windows:** `%LOCALAPPDATA%\Google\Picasa3\db3\`
* **macOS:** `~/Library/Application Support/Google/Picasa3/db3/`

### 🗄️ Основні файли бази даних:
* **`.pmp` файли (Picasa Database Tables):** Двійкові таблиці колоночного типу (наприклад, `albumdata.pmp`, `imagedata.pmp`, `facedata.pmp`, `videodata.pmp`).
* **`thumbs_index.db` & `thumbs2.db`:** Кєш мініатюр для миттєвої прокрутки у сітці Light Box без зчитування важких оригінальних файлів з диску.
* **`dbhash.xml`:** XML-файл перевірки цілісності індексу.

> 💡 **Резервна копійованість:** У разі збою чи видалення папки `db3`, Picasa автоматично сканує диски та повністю відновлює базу даних на основі локальних файлів `.picasa.ini`.

## 4. Обробка стандартних метаданих (EXIF, IPTC, XMP)

Picasa працює зі стандартними метаданими файлів зображень:

| Тип метаданих | Зчитування Picasa | Запис на диск (Write to File) |
| :--- | :--- | :--- |
| **EXIF Date / Time** | Зчитує дату створення зйомки для сортування в каталозі | Не змінюється (зберігає оригінальний час зйомки) |
| **EXIF Camera Specs** | Зчитує ISO, витримку, діафрагму, фокусну відстань, модель камери | Пропускає без змін |
| **EXIF GPS Coords** | Зчитує широту та довготу для позначення на карте | Записує нові GPS-координати в EXIF при геотегінгу в Places |
| **IPTC / XMP Captions** | Зчитує опис фотографії | Записує підпис фото у поле `IPTC:Caption-Abstract` та `XMP:dc:description` |
| **IPTC Keywords** | Зчитує теги | Записує теги у поля `IPTC:Keywords` та `XMP:dc:subject` |
| **XMP Face Regions** | Зчитує розмітку облич | Увімкнення функції *"Write name tags to photo"* записує обличчя у стандарт `MWG Face Regions` (`mwg-rs:Regions`) |

---

## 5. Запікання метаданих при експорті (Export Baking)

Під час виконання операції **Export Picture to Folder** Picasa виконує наступні кроки з файлами та метаданими:
1. Зчитує оригінальний JPEG-файл та його EXIF-метадані.
2. Декодує та застосовує всі геометричні та колірні фільтри з `.picasa.ini`.
3. Застосовує масштабування (Resize) та стиснення JPEG згідно налаштувань.
4. Впікає текст водяного знаку (Watermark), якщо вказано.
5. Зберігає оригінальний EXIF-блок, оновлюючи теги роздільної здатності, підписів, тегів та GPS-координат.
6. Записує новий підсумковий JPEG-файл у папку призначення.
