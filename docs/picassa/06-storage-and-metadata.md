# 06. Збереження файлів, метаданих та внутрішня база даних (Storage & Metadata)

Google Picasa використовує гібридну систему збереження даних: централізовану локальну базу даних для забезпечення високої швидкості роботи та приховані локальні файли конфігурації у кожній папці для забезпечення автономності й неруйнівного редагування.

---

## 📐 Архітектура збереження та обробки даних

```
+-----------------------------------------------------------------------------------------+
|                                  ФАЙЛОВА СИСТЕМА (ПК)                                   |
|                                                                                         |
|  📁 /Pictures/Vacation/                                                                 |
|  ├── 🖼️ photo1.jpg                 <-- Оригінал з вбудованими EXIF / IPTC / XMP         |
|  ├── ⚙️ .picasa.ini                 <-- Текстовий Sidecar: правки, альбоми, обличчя     |
|  └── 📁 .picasaoriginals/                                                               |
|      ├── 🖼️ photo1.jpg             <-- Незмінений дублікат оригіналу (після Save)       |
|      └── ⚙️ .picasa.ini             <-- Запечені правки та розміри оригіналу            |
|                                                                                         |
|  📁 %LOCALAPPDATA%/Google/Picasa3/db3/  <-- Центральна база даних (Binary .pmp / .pbf)    |
|  ├── 🗄️ albumdata.pmp / facedata.pmp    <-- Індекси облич, альбомів та фотографій        |
|  └── 🗄️ dbhash.xml / thumbs_index.db   <-- Кеш клейких мініатюр та хеші                 |
+-----------------------------------------------------------------------------------------+
```

## 1. Концепція неруйнівного редагування (Non-Destructive Editing)

Picasa **ніколи не модифікує оригінальний файл зображення** при застосуванні кадрування, ефектів або корекції кольору в редакторі.

1. **Рецепти змін (Edit Recipes):**
   * При зміні фотографії Picasa записує послідовність дій (інструкцій) у файл `.picasa.ini`.
   * Під час перегляду додаток на льоту накладає ці зміни на вихідне зображення в пам'яті.
2. **Операція "Save to Disk" та резервування (`.picasaoriginals`):**
   * Натискання кнопки "Save" створює приховану папку `.picasaoriginals` у тій самій директорії.
   * Незмінений оригінальний файл переміщується в `.picasaoriginals/photo1.jpg`.
   * Відредагований варіант "запікається" (bakes in) та записується на місце вихідного файлу `photo1.jpg`.
   * У `.picasaoriginals/` Picasa пише **власний** `.picasa.ini`: які правки запечено (`filters`), час модифікації (`moddate`) і розміри оригіналу ([07 §9.2](07-picasa-ini-format.md)).
   * Натискання кнопки **"Revert to Original"** повертає файл із `.picasaoriginals` на місце. Запечені правки, ймовірно, знову стають неруйнівними.

> 🕊️ **Paloma** відтворює цю модель, але **ніколи не пише `.ini`**: стан папки — у `.paloma.json`, стан оригіналів — у `.picasaoriginals/.paloma.json`. Див. §6 і [08-paloma-json-format.md](08-paloma-json-format.md).

## 2. Формат службового файлу `.picasa.ini`

> 📘 Повна специфікація формату, складена за реальними файлами, — у [07-picasa-ini-format.md](07-picasa-ini-format.md). Вона має пріоритет над цим оглядом. Paloma цей файл **лише читає** (імпорт).

Файл `.picasa.ini` — це прихований текстовий файл у кожній папці із зображеннями (ранні версії писали `Picasa.ini`). Синтаксис схожий на INI (`[секція]`, `ключ=значення`), але це не стандартний Windows INI: UTF-8 без BOM, CRLF, пробіли у значеннях значущі, і Picasa розбирає його власним парсером.

### 📜 Приклад вмісту файлу `.picasa.ini`:

```ini
[Picasa]
name=Карпати 2024
date=45422.500000
P2category=Folders on Disk
[.album:c9ea9fa67022f38a3c771894d2a8a468]
name=Гори
token=c9ea9fa67022f38a3c771894d2a8a468
date=2024-05-09T12:00:00+03:00
[Contacts2]
6a71f8e2190823ab=Олена Шевченко;olena@gmail.com;
[IMG_0042.jpg]
star=yes
backuphash=52410
rotate=rotate(1)
albums=c9ea9fa67022f38a3c771894d2a8a468
crop=rect64(34901f42d2a4e8d8)
filters=crop64=1,34901f42d2a4e8d8;autolight=1;sepia=1;
faces=rect64(579922efa1cce2aa),6a71f8e2190823ab
[IMG_0043.png]
caption=Схід сонця на вершині
keywords=гори,схід сонця
```

Що варто помітити в прикладі:

* `[Picasa] date` — OLE Automation Date (дні від 1899-12-30, локальний час). Дата альбому — ISO 8601.
* Альбом описано секцією `[.album:<token>]`, а фото посилається на нього через `albums=`.
* `[Contacts2]` — рівно три поля `ім'я;email;gaia_id`, тож порожній `gaia_id` дає один `;` у кінці.
* `caption` і `keywords` Picasa пише в `.ini` **лише для не-JPEG**. Для JPEG вони йдуть в IPTC самого файлу (§4).
* `crop=` дублює останній `crop64` з `filters`. Джерело істини — `filters`.

---

### 🔍 Детальна специфікація ключів `.picasa.ini`:

#### 1. `crop=rect64(...)` та `faces=rect64(...)` (64-бітне кодування прямокутників)
Picasa використовує 64-бітні шістнадцяткові числа (до 16 hex-символів) для кодування нормованих координат прямокутників (кадрування або обличчя). Провідні нулі Picasa не пише, тож рядок спершу доповнюють нулями зліва до 16 символів:

* **Приклад:** `rect64(579922efa1cce2aa)`
* **Алгоритм декодування:**
  1. Доповнений рядок розбивається на чотири 16-бітні підрядки (по 4 hex-символи):
     * `Left (X1)`   = `5799` (Hex) = `22425` (Dec)
     * `Top (Y1)`    = `22ef` (Hex) = `8943`  (Dec)
     * `Right (X2)`  = `a1cc` (Hex) = `41420` (Dec)
     * `Bottom (Y2)` = `e2aa` (Hex) = `58026` (Dec)
  2. Значення нормуються шляхом ділення на $65535$ ($2^{16}-1$):
     * $x_1 = 22425 / 65535 \approx 0.3421$ ($34.21\%$ від лівого краю)
     * $y_1 = 8943 / 65535 \approx 0.1364$ ($13.64\%$ від верхнього краю)
     * $x_2 = 41420 / 65535 \approx 0.6320$ ($63.20\%$ від лівого краю)
     * $y_2 = 58026 / 65535 \approx 0.8854$ ($88.54\%$ від верхнього краю)
  3. Для отримання абсолютних піксельних координат значення $x_1, x_2$ множаться на ширину зображення ($W$), а $y_1, y_2$ — на висоту ($H$).

#### 2. `filters=` (Послідовність застосованих ефектів)
Містить впорядкований список фільтрів, кожен закінчується крапкою з комою. Це історія дій: фільтри застосовуються зліва направо й можуть повторюватися. Перший параметр кожного фільтра — прапорець увімкнення `1`.
* `crop64=1,<rect64>;` — Кадрування.
* `autolight=1;` / `autocolor=1;` — Auto Contrast / Auto Color.
* `enhance=1;` — I'm Feeling Lucky.
* `finetune2=1,fill,highlights,shadows,neutral,temperature;` — Вкладка Tuning.
* `sepia=1;` — Фільтр сепії.
* `bw=1;` — Чорно-білий фільтр.
* `radblur=1,x,y,size,amount;` — Soft Focus.

Повний каталог — у [07 §4.2](07-picasa-ini-format.md). Скасовані операції зберігаються окремо в `redo=`.

#### 3. `faces=rect64(...),contact_id`
Зв'язує прямокутник обличчя з ідентифікатором контакту із секції `[Contacts2]` (локальні контакти) або `[Contacts]` (контакти облікового запису Google). Кілька облич розділяються `;`. Ідентифікатор `ffffffffffffffff` означає «ігнорувати».

#### 4. `star=yes`
Позначення фотографії прапорцем "Обране" (Зірочка).

#### 5. `rotate=rotate(N)`
Поворот зображення за годинниковою стрілкою без зміни файлу ($0 = 0^\circ$, $1 = 90^\circ$, $2 = 180^\circ$, $3 = 270^\circ$). Picasa пише `rotate(0)` явно, наприклад після чотирьох поворотів.

#### 6. Інші ключі
`albums` (членство в альбомах), `text`/`textactive` (текстові шари), `redo`, `backuphash` (16-бітне значення, **не хеш вмісту**), `screensaver`, `geotag`, `hidden`, `flipped` — див. [07 §3](07-picasa-ini-format.md).

## 3. Центральна база даних Picasa DB3

Для забезпечення швидкого пошуку та миттєвого відображення тисяч фотографій Picasa зберігає індекс у центральній двійковій базі даних DB3.

### 📂 Шляхи розміщення бази даних:
* **Windows:** `%LOCALAPPDATA%\Google\Picasa3\db3\`
* **macOS:** `~/Library/Application Support/Google/Picasa3/db3/`

### 🗄️ Основні файли бази даних:
* **`.pmp` файли (Picasa Database Tables):** Двійкові таблиці колоночного типу (наприклад, `albumdata.pmp`, `imagedata.pmp`, `facedata.pmp`, `videodata.pmp`).
* **`thumbs_index.db` & `thumbs2.db`:** Кєш мініатюр для миттєвої прокрутки у сітці Light Box без зчитування важких оригінальних файлів з диску.
* **`dbhash.xml`:** XML-файл перевірки цілісності індексу.
* **`contacts.xml`:** Повні імена та email контактів.

> 💡 **Резервна копійованість:** У разі збою чи видалення папки `db3` Picasa сканує диски й відновлює базу на основі локальних файлів `.picasa.ini`. Відновлення **не повне**: розпізнані, але не названі обличчя існують лише в `db3`, а імена контактів без `[Contacts2]` у папці — лише в `contacts.xml`.

## 4. Обробка стандартних метаданих (EXIF, IPTC, XMP)

Picasa працює зі стандартними метаданими файлів зображень:

| Тип метаданих | Зчитування Picasa | Запис на диск (Write to File) |
| :--- | :--- | :--- |
| **EXIF Date / Time** | Зчитує дату створення зйомки для сортування в каталозі | Не змінюється (зберігає оригінальний час зйомки) |
| **EXIF Camera Specs** | Зчитує ISO, витримку, діафрагму, фокусну відстань, модель камери | Пропускає без змін |
| **EXIF GPS Coords** | Зчитує широту та довготу для позначення на карте | Записує нові GPS-координати в EXIF при геотегінгу в Places |
| **IPTC / XMP Captions** | Зчитує опис фотографії | Записує підпис фото у поле `IPTC:Caption-Abstract` та `XMP:dc:description` |
| **IPTC Keywords** | Зчитує теги | Записує теги у поля `IPTC:Keywords` та `XMP:dc:subject` |
| **XMP Face Regions** | Зчитує розмітку облич | Увімкнення функції *"Write name tags to photo"* записує обличчя у стандарт `MWG Face Regions` (`mwg-rs:Regions`) |

## 5. Запікання метаданих при експорті (Export Baking)

Під час виконання операції **Export Picture to Folder** Picasa виконує наступні кроки з файлами та метаданими:
1. Зчитує оригінальний JPEG-файл та його EXIF-метадані.
2. Декодує та застосовує всі геометричні та колірні фільтри з `.picasa.ini`.
3. Застосовує масштабування (Resize) та стиснення JPEG згідно налаштувань.
4. Впікає текст водяного знаку (Watermark), якщо вказано.
5. Зберігає оригінальний EXIF-блок, оновлюючи теги роздільної здатності, підписів, тегів та GPS-координат.
6. Записує новий підсумковий JPEG-файл у папку призначення.
7. Створює в папці призначення `Picasa.ini` з `P2category=Exported Pictures` (без секцій файлів, бо правки вже запечено). За цією ознакою Paloma може розпізнати папку експорту ([07 §9.1](07-picasa-ini-format.md)).

## 6. Як це робить Paloma

Paloma зберігає модель Picasa (sidecar у кожній папці, центральний індекс, оригінали в `.picasaoriginals/`), але з одним жорстким обмеженням: **файли `.ini` Paloma ніколи не пише**. Вони слугують лише джерелом імпорту.

| Picasa | Paloma |
| :--- | :--- |
| `.picasa.ini` / `Picasa.ini` у папці | Читається при скануванні (імпорт). Стан Paloma — у `.paloma.json` |
| `.picasaoriginals/<файл>` | Те саме: оригінал переміщується туди при Save |
| `.picasaoriginals/.picasa.ini` | Читається. Стан Paloma — у `.picasaoriginals/.paloma.json` |
| `filters=` (рядок) | `edits` — впорядкований масив фільтрів з розібраними параметрами |
| `rect64(…)`, OLE DATE, ARGB, радіани | Частки `left/top/right/bottom`, ISO 8601, `#rrggbb`, градуси |
| Центральна база DB3 (`*.pmp`) | SQLite — індекс, який можна відновити з `.paloma.json` і `.picasa.ini` |
| Підпис/теги JPEG пишуться в IPTC/XMP файлу | Метадані у файлах фото не змінюються: `caption`/`keywords`/`geotag` лише в `.paloma.json`. Запис у EXIF/IPTC/XMP — тільки при експорті |

Формат `.paloma.json`, правила злиття з `.picasa.ini` і процедури Save/Revert описано в [08-paloma-json-format.md](08-paloma-json-format.md).
